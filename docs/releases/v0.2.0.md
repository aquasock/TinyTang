# TinyTang 0.2.0

The second release of TinyTang: firmware for the **Sipeed Tang Console 138K**
that runs the TinyDesk Shell and the TinyDesk desktop on the board's BL616 and
loads FPGA cores from the SD card.  This release turns the single-core bench of
0.1.0 into a console with five game and music cores, a working Bluetooth
keyboard and mouse, and a card a new user can start from.

## What is in it

- **BL616 firmware**, built on Bouffalo SDK 2.3.36, identity
  `7ed12e4-dirty.45fed98`, 698,944 bytes.
  - TinyDesk Shell 0.1.6 as a console over the board's USB-C port, and the
    TinyDesk 0.1.5 desktop on HDMI and VGA through the desktop core.
  - **Bluetooth LE keyboard and mouse** (HID over GATT), paired once from the
    console or the desktop's Bluetooth window and reconnecting by themselves
    from pairings kept on the card.  The Logitech M750 mouse and the Rii K06
    combo keyboard are the devices this release was tested with.
  - **A crash recorder**: the record survives a watchdog reset in the flash
    sector and is reported once on the next boot, so a fault is visible instead
    of a silent freeze.
  - FPGA cores loaded from the card with `tangload`, each declared its PMOD
    sockets from `/tinytang.ini`; personality 8 brings the LoRa UART up from
    power-up.
  - Firmware updates over USB with no BOOT button: `tools/tinytang_flash.py`
    from a computer, `tangflash` at the prompt, or the desktop's Software
    Update app.
  - F1–F11 reach the desktop; F12 switches between the desktop and the core.
- **Desktop core** (`tinytang.bin`), ABI 1.6, TinyTang's own, built entirely
  with the open flow (yosys, nextpnr-himbaechel, apicula; no Gowin EDA).  It
  drives HDMI and VGA together and rebuilds bit for bit from its recorded
  tuple: 4,526,774 bytes, seeded at 3.
- **Five cores**, every one proven on this board:
  - **TinyNES** — FCEUmm on the core's AE350, HDMI video, sound on a Pmod I2S2,
    Wii Classic Controllers, battery saves, and Input/Video/Audio pages.
  - **TinyGBC** — gambatte on the AE350, with its own palette and colour
    correction, cartridge libraries and settings pages.
  - **TinySNES** — SNESTang on the AE350, HDMI video, Wii Classic Controllers,
    pad remapping, aspect and overscan, a master volume, and battery saves that
    survive a power cycle.
  - **Tiny89** — a TI-89 Titanium calculator.  **It needs an operating system
    image you supply yourself**; see *What you need*.
  - **TinyPhosphor** — the music player, with a playlist, cover art and an
    oscilloscope display.
- **A release card**, laid out and documented by its own `README.md`: homebrew
  cartridges for all four game systems, hardware test suites, a codec corpus,
  the manual as a TinyWiki pack, and the `.ini` files at their defaults.
  **Nothing commercial is on it**: the retail cartridges and the TI-89
  operating system that earlier cards carried for testing were removed before
  this release.
- **A reproducible build, within one checkout.**  `deps.conf` pins every
  dependency by commit or digest, `tools/fetch-deps.sh` fetches and verifies
  them, and `BUILDING.md` gives the steps and the expected hashes.  This
  firmware was built twice from scratch and both builds were byte-identical.
  **It is not reproducible across checkouts, and a fresh clone of `7ed12e4`
  will not produce the digest in *Assets*** — see *Rebuilding this file* for
  the cause, which was found after this release shipped and is fixed in 0.2.1.

## What you need

- A Tang Console 138K (GW5AST-138, revision C), powered from its power input,
  which is what selects TinyTang over Sipeed's debugger at power-up.
- A **2.4 GHz antenna on the dock's U.FL jack** (marked ANT, on the underside).
  The board ships without one, and bare it connects only at very short range.
- A Bluetooth LE keyboard and mouse.  Bluetooth Classic devices cannot connect.
- An SD card, and a computer for the first install and the first pairing.
- Per core, if you want to use it: Wii Classic Controllers for TinyNES,
  TinyGBC and TinySNES, a Pmod I2S2 on PMOD1 for sound, and **your own TI-89
  Titanium operating system image** for Tiny89 — the calculator app will not
  start without one, and no image is distributed here because Texas
  Instruments' software is not this project's to ship.  Put yours in
  `root/media/ti89/TI89Titanium_OS.89u`.

## Installing

1. Unzip the SD card archive onto an SD card, keeping its layout, and put the
   card in the dock.  Its `README.md` describes every file.
2. **First install only:** open the case, hold the BL616's BOOT button while
   powering up, and write `bl616-firmware.bin` **at `0x40000` only**, as the
   card README's quick start shows.  **Do not use `make flash`**: it writes from
   `0x0` and overwrites Sipeed's loader.  Later updates go over USB, and the
   desktop's Software Update installs the `bl616-firmware.bin` on the card.
3. Power-cycle.  The board loads the desktop core and shows its console on the
   monitor.  `platform` at the prompt reports `7ed12e4-dirty.45fed98`.
4. Connect a computer to the USB-C console port and pair the keyboard and
   mouse (`blekbd pair`, `blemouse pair`); the card's README walks through it.
   After that the computer is not needed.  Type `desktop` for TinyDesk, or
   open a game from its window in the Start menu.

The firmware was built from `7ed12e4` with the four carried TinyDesk patches
applied, which is where the `-dirty` in its identity comes from and is the
normal state of every build here.  `BUILDING.md` names the patches by digest.

**Rebuilding this file will not give you this digest.**  This release was made
before the cause was understood, and it is a defect in this release rather than
a mistake on your part.

A build of one checkout is deterministic: the same working tree rebuilt in
place, or copied wholesale to another directory and rebuilt there, produced the
same SHA-256 every time it was tried.  Across checkouts it was not, and later
measurement found why.  `cmake/tinytang_build_id.cmake` hashes every file that
`git ls-files --others --exclude-standard` names into the build identity, and
two scripts that were never committed were therefore part of the identity of
every 0.2.0 build.  The identity is a C literal compiled into the image, and a
*same-length* change to it reorders GCC's string pool, which shifts `.rodata`
and every pointer into it: measured three ways, each change moved exactly
16,845 bytes with `rom_rodata` 8 bytes larger.  No code differed — the
preprocessed input to the affected translation unit was byte-identical and the
generated assembly differed only in the order of debug string labels.

The dirty component of this firmware's identity, `45fed98`, is the hash that
contained those two files.  So no clone of `7ed12e4` can reproduce its digest,
and the identity to trust is the one quoted in *Assets*.

0.2.1 fixes this: with a clean tree, a fresh clone of the release commit at a
second path, with `scripts/apply-tinydesk-patches.sh` run, rebuilds its
firmware byte for byte, and it agrees with two clean builds of the working tree.

## Known limitations

- **Tiny89's save does not finish.**  The calculator runs, and a state file is
  written correctly, but the 4 MiB flash image the same save sends stalls with
  no progress and the session never returns.  Accepted as a known issue for
  this release rather than fixed; `docs/qualification.md` §5.1 has the
  measurements and the work a fix starts with.
- **Flip bit 12 on a personality-8 socket word is accepted and misroutes the
  UART.**  No layout this firmware can produce sets that bit, so it is
  reachable only by a host writing the socket register directly, but the
  register should refuse it.  Recorded as a deviation in
  `docs/qualification.md` §3.3.
- **Only Bluetooth LE HID devices work**, and the Xbox Wireless Controller does
  not work over Bluetooth on this board: the fault is in the BL616's binary
  Bluetooth controller.  Controllers for games go on the cores' own ports.
- **TinyNES and TinyGBC volume is a launch-time setting.**  Their players ask
  the host for their settings when a cartridge starts, so moving the slider
  mid-game takes effect on the next launch.  TinySNES's is live.
- **TinySNES has no image-layer overlay** and no room for one in block RAM, so
  anything drawn over a running SNES game is a per-core bitstream change.
- **The last pages of a long TinyWiki article** scroll linearly: a markdown pack
  has no chapter list yet, so a converted document has no contents navigation.
- Rebuilding the desktop core needs a device database generated from Gowin EDA
  1.9.11.03, which cannot be redistributed; `deps.conf` pins its digest.  The
  three toolchains are pinned by digest but hosted by their publishers.
- The OLED and rotary-encoder PMODs are not fully qualified.

reader needs before redistributing anything.

  programmer, and twelve Phosphor transport files and host tests written in
  Tang-Control by this project's author.  `THIRD_PARTY.md` names every one.

  **GPL-3.0-only**, because it derives in part from nand2mario's GPL-3.0
  nestang.  The vendor binaries the firmware links — the Bluetooth controller
  and the PHY/RF libraries from the Bouffalo SDK — carry no source and are
  covered only by that SDK's Apache-2.0.
