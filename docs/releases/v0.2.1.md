# TinyTang 0.2.1

The third release of TinyTang: firmware for the **Sipeed Tang Console 138K**
that runs the TinyDesk Shell and the TinyDesk desktop on the board's BL616 and
loads FPGA cores from the SD card.

This is a correction release. The card that 0.2.0 shipped carried a TinyPhosphor
image built with `ae350_stub.sv` — a shim that ties every AE350 output to idle —
so the board had no RISC-V player to decode audio with and the music player
could not load a track at all. The image here is the one that carries the
AE350, and it plays on HDMI and on a Pmod I2S2.

**Only two things behave differently**, and both are in the Phosphor core and
the card around it: the AE350 is back in the core, and the PMOD layout word
`i2s2_oled` is retired in favour of `lora_i2s2`. The firmware itself differs
from 0.2.0 in one internal rework with no user-visible effect.

## What is in it

- **BL616 firmware**, built on Bouffalo SDK 2.3.36, identity
  `848a575-dirty.17f81b2`, 699,008 bytes.
  - TinyDesk Shell 0.1.6 as a console over the board's USB-C port, and the
    TinyDesk 0.1.5 desktop on HDMI and VGA through the desktop core.
  - **Bluetooth LE keyboard and mouse** (HID over GATT), paired once and
    reconnecting by themselves from pairings kept on the card.  The Logitech
    K950 keyboard and M750 mouse are the devices this board was tested with.
  - **A layer of indirection behind the Bluetooth window.**  The port now
    publishes a `td_bt_ops_t` table shaped like TinyDesk's own `td_net_ops_t`,
    and the window reaches the radio through it rather than calling the
    engine directly.  Nothing visible changed: the same windows, the same scan,
    pair, forget and reconnect.  It exists so TinyDesk can adopt the surface
    upstream without anything being renamed.
  - **A crash recorder**: the record survives a watchdog reset in the flash
    sector and is reported once on the next boot.
  - FPGA cores loaded from the card with `tangload`, each declared its PMOD
    sockets from `/tinytang.ini`; personality 8 brings the LoRa UART up from
    power-up.
  - Firmware updates over USB with no BOOT button: `tools/tinytang_flash.py`
    from a computer, `tangflash` at the prompt, or the desktop's Software
    Update app.
  - F1–F11 reach the desktop; F12 switches between the desktop and the core.
- **The PMOD layout word is `lora_i2s2`.**  The retired name `i2s2_oled`
  declared a Pmod OLEDrgb that no layout produces any more.  A card that still
  says `i2s2_oled` now reads as an unknown layout and **releases both sockets**,
  which is the safe state and is reported by `tangini` at the prompt — but it
  also means no sound on a Pmod I2S2 until the line is rewritten as
  `layout = lora_i2s2`.  The card's own `tinytang.ini` declares nothing, as it
  should for a dock with no modules seated.
- **Desktop core** (`tinytang.bin`), ABI 1.6, unchanged from 0.2.0: TinyTang's
  own, built entirely with the open flow (yosys, nextpnr-himbaechel, apicula;
  no Gowin EDA), 4,526,774 bytes, seeded at 3.
- **Five cores**, four of them byte-identical to 0.2.0's:
  - **TinyNES** — FCEUmm on the core's AE350, HDMI video, sound on a Pmod I2S2,
    Wii Classic Controllers, battery saves, and Input/Video/Audio pages.
  - **TinyGBC** — gambatte on the AE350, with its own palette and colour
    correction, cartridge libraries and settings pages.
  - **TinySNES** — SNESTang on the AE350, HDMI video, Wii Classic Controllers,
    pad remapping, aspect and overscan, a master volume, and battery saves.
  - **Tiny89** — a TI-89 Titanium calculator.  **It needs an operating system
    image you supply yourself**; see *What you need*.
  - **TinyPhosphor — rebuilt, and the reason for this release.**  The core now
    carries the AE350 that Rockbox's codecs decode on, and a decoded track
    comes out on HDMI and on a Pmod I2S2 in PMOD1 together.  The image is
    `build/ship/seed-1/tiny_phosphor_ae350_player.bin`, 5,047,788 bytes; the
    player it hands the core is unchanged.
  - The reason 0.2.0's card was silent is worth recording because it was not a
    code fault.  TinyPhosphor's build gate had inherited TinyNES's rule that a
    bus clock routed through the GB20 spine kills the AE350, and applied it to
    a design where it is not true: on this core a placement that the gate
    *rejected* played audio and one it *accepted* was silent.  With four global
    clock nets against four spine pairs the net lands on GB20 in about
    forty-seven seeds of forty-eight, so the rule was discarding almost every
    usable placement and the sweep that followed it never converged.  The rule
    was removed in TinyPhosphor, and the card now carries an image built at its
    first seed.
- **A release card**, laid out and documented by its own `README.md`: homebrew
  cartridges for all four game systems, hardware test suites, a codec corpus,
  the manual as a TinyWiki pack, and the `.ini` files at their defaults.
  **Nothing commercial is on it.**  The card is 0.2.0's, with the three
  Phosphor files replaced and the README, the `tinytang.ini` example and the
  manual pack corrected; the other nine core and player images are
  byte-identical.
  - The manual's PMOD section said to write `layout = i2s2_oled`, which this
    firmware refuses.  It now documents the three layouts this firmware
    understands, and says plainly what an unknown layout does.
- **A build that is reproducible from a commit, which 0.2.0's was not.**
  `deps.conf` pins every dependency by commit or digest, `tools/fetch-deps.sh`
  fetches and verifies them, and `BUILDING.md` gives the steps and the expected
  hashes.  A fresh clone of `848a575` with
  `scripts/apply-tinydesk-patches.sh` run rebuilds `bl616-firmware.bin` at the
  digest in *Assets*, byte for byte — measured on 2026-11-08 in a clone at a
  second path, against two clean builds of the working tree.  0.2.0's firmware
  could not be reproduced this way at all; *Rebuilding this file* below says
  why, and what changed.

## What you need

- A Tang Console 138K (GW5AST-138, revision C), powered from its power input,
  which is what selects TinyTang over Sipeed's debugger at power-up.
- A **2.4 GHz antenna on the dock's U.FL jack** (marked ANT, on the underside).
  The board ships without one, and bare it connects only at very short range.
- A Bluetooth LE keyboard and mouse.  Bluetooth Classic devices cannot connect.
- An SD card, and a computer for the first install and the first pairing.
- Per core, if you want to use it: Wii Classic Controllers for TinyNES,
  TinyGBC and TinySNES, a Pmod I2S2 on PMOD1 for sound, and **your own TI-89
  Titanium operating system image** for Tiny89 — the calculator app will not
  start without one, and no image is distributed here because Texas
  Instruments' software is not this project's to ship.  Put yours in
  `root/media/ti89/TI89Titanium_OS.89u`.

## Installing

A card written for 0.2.0 works: copy the new archive over it, keeping the new
`README.md` and `bl616-firmware.bin`.  Keep your own `tinytang.ini` and any
per-system `.ini` you have edited — those hold your settings, not the
release's.

1. Unzip the SD card archive onto an SD card, keeping its layout, and put the
   card in the dock.  Its `README.md` describes every file.
2. **First install only:** open the case, hold the BL616's BOOT button while
   powering up, and write `bl616-firmware.bin` **at `0x40000` only**, as the
   card README's quick start shows.  **Do not use `make flash`**: it writes from
   `0x0` and overwrites Sipeed's loader.  Later updates go over USB, and the
   desktop's Software Update installs the `bl616-firmware.bin` on the card.
3. Power-cycle.  The board loads the desktop core and shows its console on the
   monitor.  `platform` at the prompt reports `848a575-dirty.17f81b2`.
4. Connect a computer to the USB-C console port and pair the keyboard and
   mouse (`blekbd pair`, `blemouse pair`); the card's README walks through it.
   After that the computer is not needed.  Type `desktop` for TinyDesk, or
   open a game from its window in the Start menu.
5. **If you fit a Pmod I2S2**, uncomment `layout = lora_i2s2` in
   `/tinytang.ini`.  A card carried over from 0.2.0 may say `i2s2_oled`
   instead, which this firmware refuses; rewriting that one line is what
   restores sound.

The firmware was built from `848a575` with the four carried TinyDesk patches
applied, which is where the `-dirty` in its identity comes from and is the
normal state of every build here.  `BUILDING.md` names all four patches by
digest.

The two Phosphor files are what changed: `tinyphosphor.bin` replaces 0.2.0's
4,920,812-byte stub build, and `tinyphosphor.fs.gz` is `gzip -9 -n` of the
matching `.fs`.  Converting the decompressed `.fs` back to `.bin` reproduces
the `.bin` byte for byte.

**Rebuilding this file gives you this digest.**  This is the one thing 0.2.0
could not say.  Clone `848a575`, run `scripts/apply-tinydesk-patches.sh`, build
as `BUILDING.md` describes, and the result is
`4ced55ee3a9fd21d6384d32fd4d21f480a53040914ea096378f141c05e8d6298` every time.
0.2.0's build was not reproducible across checkouts, and the cause was found
after it shipped: `cmake/tinytang_build_id.cmake` hashes every file
`git ls-files --others --exclude-standard` names into the build identity, two
never-committed scripts were therefore part of the identity of every 0.2.0
build, and the identity is a C literal compiled into the image — so a
*same-length* change to it reordered GCC's string pool and moved 16,845 bytes
of `.rodata` and every pointer into it, while no code differed at all.  Those
files are gone and the rule is now a clean tree.

One caveat, the same as 0.2.0's: the identity embeds the commit, so a build at
the `v0.2.1` tag — which sits on a commit that follows `848a575` and changes
documents — reports a different identity and a different digest.  Compare
against the digest above, not against a build of the tag.

## Known limitations

- **Uncompressed WAV underruns on TinyPhosphor.**  Every file in the card's
  codec corpus is ten seconds long, and WAV at 176.4 kB/s needs 93 percent of
  what the 2 Mbaud link carries, so it starves while FLAC, MP3 and the other
  eight formats report zero.  The numbers were measured on the earlier
  placement image and the mechanism is the link rate rather than the build, so
  it survives this release.  The fix is the 5 Mbaud link TinyMaps measured at
  431 kB/s, which is an RTL change in TinyPhosphor and not yet made.
- **The Pmod I2S2 was confirmed by ear on a different placement of the same
  RTL.**  The shipping image has been measured on the board to boot, publish
  the AE350 (`0x54504133` at `0x4000`), complete a track with zero underruns,
  and answer as core 80; the listening test that found the gate defect was on
  another seed of the same netlist, whose only difference is placement.  The
  quickest way to tell an AE350 core from the stub is
  `phosphor peek 0x4000`: `0x54504133` means an AE350 is running, `0` means it
  is not.
- **Tiny89's save does not finish.**  The calculator runs, and a state file is
  written correctly, but the 4 MiB flash image the same save sends stalls with
  no progress and the session never returns.  Accepted as a known issue rather
  than fixed; `docs/qualification.md` §5.1 has the measurements.
- **Flip bit 12 on a personality-8 socket word is accepted and misroutes the
  UART.**  No layout this firmware can produce sets that bit, so it is
  reachable only by a host writing the socket register directly, but the
  register should refuse it.  `docs/qualification.md` §3.3.
- **The Pmod OLEDrgb is no longer reachable from any layout.**  The personality
  number is still 1 on the wire, so a host that writes `0xc0` by hand can
  declare it, but no `tinytang.ini` layout produces it.  `lora_i2s2` replaced
  the layout that used to.
- **Only Bluetooth LE HID devices work**, and the Xbox Wireless Controller does
  not work over Bluetooth on this board: the fault is in the BL616's binary
  Bluetooth controller.  Controllers for games go on the cores' own ports.
- **TinyNES and TinyGBC volume is a launch-time setting.**  Their players ask
  the host for their settings when a cartridge starts, so moving the slider
  mid-game takes effect on the next launch.  TinySNES's is live.
- **TinySNES has no image-layer overlay** and no room for one in block RAM, so
  anything drawn over a running SNES game is a per-core bitstream change.
- **The last pages of a long TinyWiki article** scroll linearly: a markdown pack
  has no chapter list yet, so a converted document has no contents navigation.
- Rebuilding the desktop core needs a device database generated from Gowin EDA
  1.9.11.03, which cannot be redistributed; `deps.conf` pins its digest.  The
  three toolchains are pinned by digest but hosted by their publishers.
